# Ruby and Python: a path parameter holding `!'()*` is spelled differently from TypeScript and Go

Filed from [voxgig/likeness](https://github.com/voxgig/likeness), which builds one application in five languages against SDKs generated by sdkgen.

## What happens

Every generated SDK escapes a path or query value with its vendored struct's `escurl`. In TypeScript that is `encodeURIComponent`, and Go's `EscUrl` keeps the same characters. The Ruby and Python templates vendor an older struct, whose `escurl` escapes five characters that `encodeURIComponent` keeps:

```ruby
def self.escurl(s)
  s = s.nil? ? "" : s
  URI::DEFAULT_PARSER.escape(s, /[^A-Za-z0-9\-\.\_\~]/)
end
```

```python
def escurl(s: Any):
    "Escape URLs."
    if s == UNDEF:
        s = S_MT
    return urllib.parse.quote(s, safe='')
```

voxgig/struct has since fixed both: its Ruby port escapes `/[^A-Za-z0-9\-._~!*'()]/` (`ruby/voxgig_struct.rb:201-204` at `3ab807c`), and its Python port's `escurl` keeps what `encodeURIComponent` keeps.

## Why it matters

The same note reaches the same server by different bytes from different languages. likeness records the requests station observes at the transport, and its corpus compares them across ports, so an Obsidian vault path such as `a+b #c %d &e=f (1) Straße.md` goes out as

```
TypeScript, Go  /vault/a%2Bb%20%23c%20%25d%20%26e%3Df%20(1)%20Stra%C3%9Fe.md
Ruby, Python    /vault/a%2Bb%20%23c%20%25d%20%26e%3Df%20%281%29%20Stra%C3%9Fe.md
```

Both decode to the same file, and the plugin serves it either way, but the ports cannot agree on the wire byte for byte. likeness's Ruby port carries a declared exception for the two transcript entries this changes, which expires when the SDK is regenerated.

## Reproduction

No credentials and no network: the transport is the SDK's own `utility.fetcher` seam, recording the URL it is given.

```ruby
$LOAD_PATH.unshift('obsidian-sdk/rb')
require 'Obsidian_sdk'

seen = []
fetcher = lambda do |_ctx, url, _fetchdef|
  seen << url
  [{ 'status' => 200, 'statusText' => 'OK', 'headers' => {}, 'json' => -> { { 'content' => 'x' } }, 'body' => '' }, nil]
end
client = ObsidianSDK.new('base' => 'https://127.0.0.1:27124', 'apikey' => 'k', 'utility' => { 'fetcher' => fetcher })
client.Vault.load({ 'id' => 'a+b (1).md' })
puts seen.last
```

```
https://127.0.0.1:27124/vault/a%2Bb%20%281%29.md
```

The TypeScript SDK at the same revision, through the same seam, sends `https://127.0.0.1:27124/vault/a%2Bb%20(1).md`.

## Where the fix belongs

The vendoring route: resync the Ruby and Python struct ports into the scaffold at a tag that carries the `escurl` fix, then regenerate the SDKs' `rb` and `py` targets. No model change is involved.
