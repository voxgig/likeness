# `explain` rejects the code as it is printed, and a large minority of registered codes have no text

Two defects in the same workflow. `aontu help codes` prescribes the repair loop as *"Read the code in the brackets, then look it up: `aontu explain <code>`"* — and neither half works as written.

## 1. The code in the brackets is not a code `explain` accepts

Error output prints the namespaced form:

```
$.note.n1.id: constraint [conflict]
  [aontu/constraint]: Cannot unify values at path $.note.n1.id
```

Copying what is in the brackets fails:

```
$ aontu explain aontu/constraint
aontu: no such error code `aontu/constraint`
aontu: `aontu explain --list` lists every registered code
```

Stripping the namespace works:

```
$ aontu explain constraint
code:  constraint
class: conflict

This value does not satisfy the constraint. ...
```

The one form the tool actually shows a user is the one form `explain` refuses. Accepting an optional `aontu/` prefix would close it.

## 2. A large minority of registered codes have no text

```
$ aontu explain compat_required_added
code:  compat_required_added
class: compat

(no explanation text is registered for this code)
```

Same for `sub_unresolved`. **29 of 168 registered codes have no text**, and the `compat` class is 13 out of 13 — every one of them undocumented.

The gap is not evenly spread: the `compat` class is entirely undocumented, and those are exactly what `breaking --against` reports. A release gate on `breaking` surfaces `compat_required_added`, the reader does the prescribed lookup, and gets nothing — at the moment they most need it, because a compat verdict is the one that blocks a release.

## Why it matters to us

[voxgig/likeness](https://github.com/voxgig/likeness) specifies its application in aontu and gates every change on it. Our `PROCESS.md` now carries the line "to look up an error code, strip the `aontu/` prefix first", which is a workaround in our documentation for a one-line fix in yours.

The error reports themselves are excellent — code, path, expected, actual, and both source lines with row and column. That quality is what makes the missing second half conspicuous rather than expected.
