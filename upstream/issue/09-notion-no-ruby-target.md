# notion-sdk has no Ruby target, where the other three do

## What is there

```
$ git ls-files | awk -F/ '{print $1}' | sort -u
.github .sdk AGENTS.md ... c docs go go-cli go-mcp js lua php py ts
```

No `rb/`, and no gemspec anywhere in the repository. The other three are consistent with each other:

| Repository | Targets |
|---|---|
| `joplin-sdk` | c go go-cli go-mcp lua php py **rb** ts |
| `obsidian-sdk` | c go go-cli go-mcp lua php py **rb** ts |
| `linear-sdk` | c go go-cli go-mcp lua php py **rb** ts |
| `notion-sdk` | c go go-cli go-mcp **js** lua php py ts |

So notion has `js` where the others have `rb`. Whether that is a deliberate substitution or a target list edited once and not propagated, it makes notion the only one of the four that a Ruby consumer cannot use.

## Why it matters

[voxgig/likeness](https://github.com/voxgig/likeness) builds one application in five languages — TypeScript, Go, Python, Ruby and C — over these four sources, and holds the five to identical output. With no Ruby target there is no Notion SDK for the Ruby port to depend on, and no offline test mode for Notion in Ruby either, since there is nothing to construct. One of twenty source-by-port combinations simply does not exist.

We have recorded it as an absent key in our source registry rather than papering over it, and our registry check now reports it as a warning on every run. But it is not something a consumer can fix.

## Suggested direction

Add the `rb` target and regenerate, if its absence is an oversight. If `js` was meant to replace `rb` for this API, saying so in the README would be enough — a consumer currently has to diff four repositories to notice.
