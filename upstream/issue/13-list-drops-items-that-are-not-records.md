# Ruby, Python and Go: a `list` whose items are not records returns entities with no data

Filed from [voxgig/likeness](https://github.com/voxgig/likeness), which builds one application in five languages against SDKs generated by sdkgen.

## What happens

`make_result` builds one entity per item of a `list` response. TypeScript hands every item to the entity, whatever it is:

```ts
for (let entry of resdata) {
  const ent = entity.make()
  ent.data(entry)
  result.resdata.push(ent)
}
```

Ruby, Python and Go hand it over only when it is a record:

```ruby
ent.data_set(entry) if entry.is_a?(Hash)
```

and Ruby's `data_set` would turn anything else into `{}` in any case (`ProjectNameHelpers.to_map(...) || {}`). An item that is a string, a number or a list becomes an entity with empty data.

## Why it matters

The Obsidian Local REST API answers `GET /vault/` with `{"files": ["Welcome.md", "projects/"]}`, and the vault entity's list point unwraps `body.files`. From TypeScript, `Vault().list()` gives two entities whose `data()` are the two names. From Ruby, it gives two entities whose `data_get` are `{}`: the request succeeds, the count is right, and every name is gone. A vault cannot be walked from its root, which is the only way the plugin offers to list it.

The SDKs' offline test mode lists records, so no offline test can see this; likeness found it in its wire suite against a mock of the plugin. Its Ruby port walks a vault correctly offline and refuses the live root listing as `source-unavailable`, and its wire test for the walk is skipped, saying why.

## Reproduction

No credentials and no network: the transport is the SDK's own `utility.fetcher` seam, answering the root listing as the plugin does.

```ruby
$LOAD_PATH.unshift('obsidian-sdk/rb')
require 'Obsidian_sdk'

fetcher = lambda do |_ctx, _url, _fetchdef|
  body = { 'files' => ['Welcome.md', 'projects/'] }
  [{ 'status' => 200, 'statusText' => 'OK', 'headers' => {}, 'json' => -> { body }, 'body' => '' }, nil]
end
client = ObsidianSDK.new('base' => 'https://127.0.0.1:27124', 'apikey' => 'k', 'utility' => { 'fetcher' => fetcher })
p client.Vault.list.map(&:data_get)
```

```
[{}, {}]
```

The TypeScript SDK at the same revision, through the same seam, gives `["Welcome.md","projects/"]`.

## Where the fix belongs

The templates: `make_result` in every target should pass an item to the entity whatever its type, as TypeScript does. That alone is not enough in Ruby, Python or Go, whose entity fragments keep their data as a map and turn any other value into an empty one (`Entity.fragment.rb:71`, `Entity.fragment.py:58`, `Entity.fragment.go:96`), so the fix also needs a decision about where an entity's scalar data lives.
