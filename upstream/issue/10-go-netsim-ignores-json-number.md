# Go: every numeric feature option is silently ignored when it arrives as `json.Number`

Filed from [voxgig/likeness](https://github.com/voxgig/likeness), which builds one application in five languages against SDKs generated by sdkgen.

## What happens

`foptInt` and `foptNum` coerce a feature option with a type switch and **no default branch**:

```go
func foptInt(options map[string]any, key string, def int) int {
	if options == nil {
		return def
	}
	switch n := options[key].(type) {
	case int:     return n
	case int64:   return int(n)
	case float64: return int(n)
	case float32: return int(n)
	}
	return def          // <- json.Number lands here
}
```

`encoding/json` produces `json.Number` for **every** number whenever a decoder has `UseNumber()` set — the standard way to read a JSON document without turning integers into float64. Such a value matches no case, falls through, and **the configured option is replaced by the default without any error**.

## Why it matters

This is not confined to the test feature. `foptInt`/`foptNum` are the option readers for ten features, and these are the options they read:

| Feature | Options silently reset to their defaults |
|---|---|
| `retry` | `retries`, `minDelay`, `maxDelay`, `factor` |
| `ratelimit` | `rate`, `burst` |
| `timeout` | `ms` |
| `cache` | `ttl`, `max` |
| `test` | `failTimes`, `failStatus`, `errorTimes`, `latency`, `min`, `max` |
| `netsim` | the above plus `failEvery`, `failRate`, `rateLimitTimes`, `retryAfter`, `seed` |

So a service reading its SDK configuration from a JSON file the ordinary careful way gets **a 30-second timeout when it asked for 1.5 seconds**, two retries when it asked for five, and no rate limit at all. Nothing logs, warns or returns an error — the only symptom is behaviour that quietly is not what the configuration says.

In the test and netsim features the same gap inverts a test's meaning: `failTimes` set that way does nothing, the simulated failure never happens, the request succeeds, and a test that believes it is exercising a failure path is exercising the success path **and passing**.

## Reproduction

No credentials, no network, no SDK — `foptInt` below is copied verbatim from the template.

```go
package main

import (
	"encoding/json"
	"fmt"
	"strings"
)

func foptInt(options map[string]any, key string, def int) int {
	if options == nil {
		return def
	}
	switch n := options[key].(type) {
	case int:     return n
	case int64:   return int(n)
	case float64: return int(n)
	case float32: return int(n)
	}
	return def
}

func decode(src string, useNumber bool) map[string]any {
	d := json.NewDecoder(strings.NewReader(src))
	if useNumber {
		d.UseNumber()
	}
	var m map[string]any
	_ = d.Decode(&m)
	return m
}

func main() {
	const cfg = `{"ms":1500,"retries":5,"rate":10}`
	plain, numbered := decode(cfg, false), decode(cfg, true)

	fmt.Printf("%-22s %-14s %s\n", "option (default)", "encoding/json", "with UseNumber()")
	for _, c := range []struct {
		key string
		def int
	}{{"ms", 30000}, {"retries", 2}, {"rate", 0}} {
		fmt.Printf("%-22s %-14d %d\n",
			fmt.Sprintf("%s (%d)", c.key, c.def),
			foptInt(plain, c.key, c.def), foptInt(numbered, c.key, c.def))
	}
}
```

Output:

```
option (default)       encoding/json  with UseNumber()
ms (30000)             1500           30000
retries (2)            5              2
rate (0)               10             0
```

The same document, decoded the other standard way, turns a 1.5-second timeout into a 30-second one.

## Suggested fix, in order of preference

1. **Accept `json.Number`** in `foptInt` and `foptNum` — one case each, calling `.Int64()` / `.Float64()`.
2. **Fail loudly on a type it cannot read**, naming the option and the type. Even without (1) this turns a silent wrong answer into a clear one, which is the part that matters. `foptBool`, `foptStr`, `foptMap`, `foptList` and `foptStrList` have the same shape and the same silence.
3. Document the accepted types, so a consumer reading the docs rather than the template knows.

(1) and (2) together would be ideal: accept the type, and refuse anything still unrecognised rather than dropping it.

## What we do meanwhile

Our Go corpus harness rewrites every `json.Number` under a feature's options to `int` before handing them to the SDK, and a test asserts that a `failStatus` set that way actually reaches it — so a regression in that workaround is reported directly rather than as a puzzling diff. It is a workaround in our repository for a coercion that belongs in the template.
